# R1 — Load source and baseline (M) — status: open

A thousand simulated drivers move along a real city's roads, misbehave like real devices
(reordering, duplicates, reboots, connection drops), and the pipe from device to hot state
reports its own throughput, lag and latency. The first baseline every later number is
compared to, including a step load to this machine's limit.

## In
- **Simulator at fleet scale.** N drivers (configurable; 1,000 for the demo) in one process,
  with speeds per road class, stops, and connection drops. HTTP client pool sized for the load
  (Go's default keeps 2 idle connections per host).
- **Road network of the simulated district** (downtown Cairo, bbox S 30.030 W 31.225 N 30.060
  E 31.255), from OpenStreetMap:
  - *Source and provenance.* One Overpass query, committed; the raw response is never
    committed. A preprocessor writes a compact graph that is committed and embedded in the
    simulator (≤ 512 KB). The graph records the query, bbox and Overpass `osm_base` timestamp.
    `make roadgraph` regenerates it. ODbL attribution in `simulator/README.md`.
  - *Drivable roads only.* Motor-vehicle `highway` classes; footways, paths, steps, cycleways,
    `access=private|no` and `area=yes` excluded.
  - *Directed and routable.* `oneway=yes|-1` and roundabouts honoured; the graph keeps the
    largest strongly connected component, so every node can reach every other and no driver
    is trapped at a one-way dead end.
  - *On the street, not across blocks.* Edges keep the full way geometry (every shape node, not
    only intersections); positions are interpolated along it.
  - *Routes, not random walks.* Each driver drives the shortest path by travel time
    (length ÷ class speed) from its position to a random destination node, stops, then picks the
    next. Turn restrictions are not modelled.
- **Road-data checks**, each derived twice:
  - graph stats (nodes, directed edges, km of drivable road, one-way edges) from the
    preprocessor vs. an independent count over the raw Overpass response (`jq`);
  - on-road: every simulator-generated point lies within 1 m of a graph edge (unit test);
    after a run, every projected position in Redis lies within 1 m of an edge (post-run
    check vs. the graph);
  - routable: no route traverses a one-way edge against its direction (unit test over sampled
    routes); visual check of drivers over the basemap at zoom 17, screenshot kept as evidence.
- **Device sessions (decision 4).** Every report carries a device session id and a device
  sequence number that restarts at 1 per session.
  - Session id is a per-driver boot counter held by the simulator (the simulator is the
    device, so this is device storage). An injected reboot increments it. A simulator process
    start seeds every counter once from the host clock (Unix seconds), standing in for device
    storage that survives a process restart. Injected reboots and injected clock steps never
    read the clock.
  - `device_ts` is never used for ordering.
  - Event id becomes `fleet:driver:session:seq`; `position.SchemaVersion` becomes 2.
  - Upgrade from R0: a record or hash with no session is session 0 (v1 records are still
    inside the 3-day retention), so R0 state never holds a driver behind it.
- **Invariant 4 restated** in PLAN §Invariants together with ADR 0004: "For each driver, the
  projected (device session, device sequence) never decreases in lexicographic order; after
  quiescing it equals the maximum over that driver's valid reports in `position.reported`."
- **Adversarial injection**, each switchable and counted by the simulator: out-of-order
  delivery, duplicate sends, device reboots (session + 1, seq back to 1), connection drops,
  device clock stepping back. Every invariant-4 scenario ends by sending one stale report per
  driver after that driver's newest report.
- **Projector ordering by (session, seq), lexicographic.** An older pair never overwrites
  current state. Counts refusals (not newer than current).
- **Ingest dedupe.** Exact (driver, session, seq) keys only, in a bounded LRU per replica.
  Never "at or below the last seen": that would drop reordered reports that decision 4 sends
  to history. Reports how many projector calls it saved; if negligible, it is written down
  as decoration and removed.
- **Bounded queues and load shedding (decision 8).** Ingest caps in-flight produces and
  answers 503 + `Retry-After` when full (`reason=cap`) or when the log does not ack in time
  (`reason=timeout`; the record may still land). The franz-go producer buffer is sized from
  measured load. The simulator honours `Retry-After` with jitter and a bounded per-device
  buffer, and counts what it drops.
- **Metrics.** Prometheus-format metrics from ingest, projector (incl. skipped invalid records,
  offset lag, time lag = now − `ingest_ts` of the last applied record) and simulator. One plain
  Prometheus Deployment (not kube-prometheus-stack) with a scrape config shared by compose and
  kind, and one Grafana board: ingest rate, accepted / shed by reason / duplicate counts,
  offset and time lag, latency percentiles.
- **Ingest reachable from the host on kind:** a NodePort and a kind port mapping (needs a
  cluster recreate), so the generator runs outside the Docker VM.
- **First checker** (`checker/`): invariant 4 after quiescing (load stopped, projector at the
  topic's high-water marks), two parts: (a) end state — projected (session, seq) equals the
  per-driver maximum over the log, deduped by event id, v1 records read as session 0;
  (b) over time — subscribed to `fleet:*:positions` during the run, each driver's published
  updates strictly increase (pub/sub gaps cannot break this). It also replays the log per driver
  and counts records at or below the running maximum.
- **Step load** on kind, the baseline environment, with the criterion below fixed before the run.

## Out
Cloud, autoscaling, zones, orders, cells and coalescing in the live gateway, history store,
consumer-side pause-on-lag beyond the projector's synchronous poll loop (decision 8, R8),
gateway replicas behind a balancer (R2), auth beyond the static token, fixing the bottleneck
the step load finds (R8; R1 names it with evidence).

## Measurement rules for this slice
- **Machine** (verified 2026-11-05, `rtk proxy sysctl -n hw.ncpu hw.memsize machdep.cpu.brand_string`,
  `rtk proxy docker info --format '{{.NCPU}} cpus, {{.MemTotal}} bytes'`): Apple M4 Pro, 12
  cores, 24 GiB host; Docker VM 4 CPUs, 8,393,641,984 bytes. The Docker VM is the system's
  ceiling, not the host.
- **Generator outside the system.** The simulator runs on the host; its CPU and send rate are
  recorded per step. If the generator saturates first, that is the finding.
- **Transport calibration first.** Before the step load, the generator drives a null server
  inside the VM that answers 202 at once, through the same port mapping; its ceiling is the
  transport limit, and any step above it measures Docker Desktop, not flotilla.
- **Every load shape states:** drivers, report period, injection mix, partition count of
  `position.reported` (6, an R0 placeholder), trace sampling ratio (assumed 100% today: no
  sampler is configured in `internal/telemetry`; Tempo is in-memory and part of the load), and
  that no WebSocket client is connected (the live gateway pushes every update uncoalesced).
- **Steps:** PLAN's shape (`PLAN.md:457`), 10 minutes per step, the first 5 minutes warm-up,
  the last 5 measured.
- **A step holds** if over its measured window:
  - shed rate (503s ÷ ingest requests) < 1%;
  - offset lag at window end ≤ lag at window start + 3,000 (poll batch 500 × 6 partitions,
    the commit sawtooth);
  - ingest handler p99 < 250 ms.
  The limit is the last step that holds. Thresholds are assumed reasonable, not derived.
  Loss is reported separately: unique generated reports not in the log ÷ unique generated.
- **Restarts.** A projector or ingest restart inside a measured window voids the window; at or
  past the limit, the restart is itself the bottleneck finding.
- **No device_ts → ingest_ts latency is reported:** host and VM clocks drift (R0's host sleep).
- **Second derivations** (disagreement is a finding):
  - ingest rate: ingest accepted counter vs. topic end-offset delta (`kafka-get-offsets`) over
    the window; expected offset delta ≥ accepted (timeout 503s may land);
  - shed: simulator 503 counter vs. ingest 503 counter by reason; only `reason=cap` is matched
    against "not written";
  - lag: offset lag (projector metric, cross-checked with `kafka-consumer-groups --describe`)
    vs. time lag, compared as window averages;
  - latency: ingest handler histogram vs. simulator-measured request latency; pipeline latency
    (`ingest_ts` → projector applied, both in the VM) vs. sampled Tempo traces;
  - invariant 4: checker verdict (end state and over time) plus the checker's replayed
    at-or-below count vs. the projector's refusal counter (projector ≥ checker, since it also
    refuses redeliveries).

## Exit criteria
- [ ] `demo/r1.sh` from a clean checkout: 1,000 drivers moving on the map; Grafana board shows
  ingest rate, lag and latency; ends with the checker passing. Time recorded in `docs/results/R1.md`.
- [ ] Road network: graph regenerated by `make roadgraph` from the committed query; stats
  derived twice; zero off-road positions in Redis after the 1,000-driver demo; zero one-way
  violations over sampled routes; screenshot of drivers on streets at zoom 17.
- [ ] Baseline numbers in README with their commands and second derivations, on kind: ingest
  rate, ingest p50/p99, pipeline p50/p99, offset and time lag, shed rate at 1,000 drivers.
- [ ] Transport ceiling measured; step load to this machine's limit by the criterion above:
  steps, the last step that holds, the first bottleneck named with evidence (CPU, lag or shed
  by component, generator and transport ruled out).
- [ ] Invariant 4 passes, end state and over time, with injected reordering, duplicates, reboots,
  clock step-back and trailing stale reports; injected counts, checker at-or-below count and
  projector refusal count reported beside the verdict.
- [ ] Load shedding observed: a run past the limit shows `reason=cap` 503 + `Retry-After`, the
  simulator backing off, and no crash; shed counts derived twice.
- [ ] Invariant 4 restated in PLAN; ADR 0004 (ordering and late data) and ADR 0008
  (backpressure: ingest hop and simulator; consumer side stays proposed until R8) accepted
  after design-critic review.
- [ ] `docs/results/R1.md`: every number with its command, window, load shape and second derivation.
- [ ] Number of sittings R1 actually took, recorded.
- [ ] Tag `v0.1`.

## R0 Deferred items, triaged
- Device session in seq and event id (decision 4) — **In.**
- Simulator seq frozen when the clock steps back — **In**, resolved by the boot-counter session
  above (seq is a per-session counter; the clock is read once per process start, never per
  report). Holds only with that generator; a time-ordered session id would reintroduce it.
- Ingest in-flight limit and load shedding with 503 + `Retry-After` (decision 8) — **In.**
  Verified 2026-11-05: ingest already answers 503 with `Retry-After: 1` when produce fails or
  times out (`services/ingest-gateway/internal/ingest/ingest.go:72-76`), but has no in-flight cap.
- franz-go producer buffer sizing — **In**: sized from the 1,000-driver and step-load numbers.
- Projector one EVALSHA per record — **Deferred to R8.** The step load names it if it is the
  bottleneck; fixing it is R8. Verified 2026-11-05: one `Apply` per record inside the poll loop
  (`services/location-projector/internal/projector/consumer.go:71-75`).
- Skipped-invalid-records metric for the checker — **In** (counter exported). Recording the
  validator version for replay stays Deferred to R3 (decision 10).
- Projector exits on commit `UNKNOWN_MEMBER_ID` instead of rejoining — **Deferred** to R4a
  (consumer restarted mid-burst). Safe under at-least-once; covered here by the restart rule
  under Measurement.
- The first checker, invariant 4 — **In.**
- Also affecting measurement, carried as stated conditions rather than fixed: 6 placeholder
  partitions, Tempo in memory at full sampling, live-gateway fan-out without coalescing.

## Deferred (found during the slice, not done here)
- OSM turn restrictions (`type=restriction` relations) and traffic signals are not modelled;
  routes are shortest by travel time on the directed graph only.
- Other districts and cities (PLAN: simulator works for any city given an extract) — the
  preprocessor takes a bbox, but only downtown Cairo is built and checked in R1.
